## [06-02-2026] - Исправление ошибок обработки БНД (410 документов)

### Добавлено
- Интерливинг таблиц и текста по Y-координатам: таблицы теперь вставляются на правильное место в документе (а не в конец страницы)

- Извлечение версии документа (ИЗДАНИЕ/РЕВИЗИЯ) с титульной страницы через OCR

### Изменено

## [06-11-2025] - Правила итеративной работы с BPMN файлами

### Добавлено
**Новый раздел в БЛОК 5 (.cursorrules):**

**"🛠️ Работа с BPMN файлами"** - подробное руководство по созданию и редактированию BPMN XML:

**Философия работы:**
- ✅ **РАЗРЕШЕН И РЕКОМЕНДУЕТСЯ** итеративный подход (несколько этапов)
- ❌ НЕ пытаться создать идеальный BPMN за один проход
- Обоснование: BPMN XML - большие файлы (1500-2000+ строк кода)

**Стандартные инструменты разработки:**
1. `write` - создание нового BPMN (минимальная структура)
2. `search_replace` - редактирование (ВСЕГДА с достаточным контекстом 5-10 строк)

**Рекомендуемый порядок создания (6 этапов):**
- **Этап 1:** Базовая структура (write) → Pool, Lane, Start/End
- **Этап 2:** Добавление lanes и задач (search_replace) → без визуализации

- **Этап 6:** Валидация и исправления (grep + Camunda Modeler)

**Правила итеративной работы:**
- ✅ Работать этапами (структура → детали)
- ✅ Проверять после каждого этапа (read_file + grep)
- ✅ Исправлять ошибки по мере обнаружения
- ❌ НЕ создавать весь BPMN за один `write`
- ❌ НЕ использовать короткие фрагменты в `search_replace`
- ❌ НЕ пропускать валидацию между этапами

**Контроль качества:**
- Проверка результата изменения (read_file)
- Проверка на дубликаты (grep -c)
- Проверка структуры (lanes в SubProcess)
- Валидация в Camunda (после крупных изменений)

**Работа с большими контекстами:**
- ❌ ПЛОХО: короткий контекст (может быть несколько совпадений)

## [05-11-2025] - Универсальный алгоритм структурирования процессов

### ✅ Формализация логики принятия решений для структуры BPMN

**Цель:** Создать прозрачный, воспроизводимый алгоритм для структурирования любого документа в BPMN диаграмму.

### Добавлено

#### Раздел "1.2 Автоматическое структурирование работы" (115 строк)

**5-шаговый алгоритм принятия решений:**

**Шаг 1: Оценка размера документа**
- Таблица: страницы × разделы → подход к моделированию
- < 50 страниц, < 5 разделов → одна детальная диаграмма
- 50-150 страниц, 5-10 разделов → главная + SubProcess для крупных разделов
- > 150 страниц, > 10 разделов → главная + SubProcess для всех разделов

**Шаг 2: Анализ каждого раздела по 5 критериям (балльная система)**
1. Отдельная тема? → +1 балл
2. Своя ролевая модель? → +1 балл
3. Относительная автономность? → +1 балл
4. >= 3 задач? → +1 балл
5. Есть вариативность? → +1 балл

**Решение:** 3-5 баллов → SubProcess, 0-2 балла → задачи в главной диаграмме

**Шаг 3: Формирование главной диаграммы**
- 3 принципа группировки: по фазам жизненного цикла, по функциональным областям, по параллельности
- Оптимальная структура: 3-5 lanes, 5-10 SubProcess

**Шаг 4: Выбор типа элемента**
- Таблица сравнения SubProcess vs Call Activity (4 критерия)
- **Правило:** ВСЕГДА использовать SubProcess для структурирования в один файл
- Call Activity только для реюза между разными процессами

**Шаг 5: Правила работы и документирование**
- Работать автоматически по критериям, без согласований
- Документировать обоснование структуры в `[Процесс].md`

### Техническая архитектура

**Принципы разработки:**
- **SOLID**: 
  - Single Responsibility - класс OCRPrompts отвечает только за хранение промптов
  - Open/Closed - легко добавить новые типы промптов без изменения существующего кода
- **KISS**: Простые, понятные шаблоны промптов
- **DRY**: Переиспользуемые промпты через метод get_prompt_by_type()

**Архитектурное решение:**
```
PDF Page → Render (300 DPI) → DeepSeek-OCR (BPMN prompt) 
    → Structured Markdown → (future: Parser → IR → BPMN XML)
```

**Типы диаграмм для тестирования:**
1. **Простые BPMN диаграммы**
   - Элементы: процессы, шлюзы, события
   - Промпт: `bpmn`

2. **Сложные схемы с смешанными нотациями**
   - Элементы: несколько нотаций + текстовые пояснения
   - Промпт: `complex_diagram`

### Следующие шаги

**После тестирования (если качество >90%):**
1. Разработать `BPMNDetector` - автоматическое определение BPMN страниц
2. Разработать `BPMNParser` - парсинг Markdown → BPMN IR
3. Разработать `BPMNFormatter` - IR → BPMN 2.0 XML
4. Интегрировать в `PDFToContextPipeline`

**Если точность <80%:**
1. Собрать датасет (50-100 аннотированных примеров)
2. Fine-tuning DeepSeek-OCR на BPMN данных
3. Повторное тестирование

### Изменено

  - **Этап 1**: Извлечение структуры и текста нативно (для всех документов)
  - **Этап 2**: OCR только для графических элементов
  - **Этап 3**: Встраивание результатов OCR в структуру по bbox
- **Ключевой принцип**: Сохранение оригинального layout документа

  - Удалён `ContentRouter` (маршрутизация native/OCR/hybrid больше не нужна)
  - Удалён `HybridHandler` (всегда используем поэтапный подход)
  - Добавлен `StructurePreserver` (встраивание OCR в структуру)
- **NativeExtractor** теперь:
  - Извлекает ВСЮ структуру документа (текст + позиции графики)
  - Создаёт placeholder'ы для графики с bbox
  - Возвращает упорядоченный список блоков
- **OCRClient** теперь:
  - Работает только с графическими элементами
  - Получает регион по bbox
  - Возвращает распознанный контент для встраивания
- **Pipeline**:
  - Всегда начинает с native extraction
  - Затем обрабатывает графику через OCR
  - Встраивает результаты обратно в структуру

### Обоснование
Новая архитектура лучше сохраняет оригинальную структуру документа, так как:
1. Структура и текст извлекаются первым проходом
2. OCR результаты встраиваются точно в те же позиции (по bbox)
3. Порядок элементов соответствует оригиналу

## [28-10-2025] - Создан модуль PDF to Context для интеллектуальной обработки PDF

### Добавлено
- **Модуль `pdf_to_context/`** - полнофункциональная система извлечения контекста из PDF
- **Архитектура с интеллектуальной маршрутизацией** (SOLID/KISS/DRY принципы)
- **Core компоненты:**
  - `PDFParser` - управление PDF файлами (PyMuPDF)
  - `PageAnalyzer` - анализ плотности текста, типа layout, покрытия графикой
  - `ContentRouter` - маршрутизация (native/OCR/hybrid) с приоритетом точности
- **Extractors (извлечение контента):**
  - `NativeExtractor` - нативное извлечение (PyMuPDF + pdfplumber)
  - `OCRClient` - HTTP клиент для DeepSeek-OCR микросервиса
  - `HybridHandler` - гибридная обработка (текст нативно, графика через OCR)
- **IR (Intermediate Representation):**
  - `IRBuilder` - построение промежуточного представления
  - `StructureAnalyzer` - анализ структуры (заголовки, списки, таблицы, иерархия)
  - Модели данных: `IR`, `IRBlock`, `IRRelation`, `DocumentMetadata`
- **Output форматирование:**
  - `MarkdownFormatter` - форматирование в структурированный Markdown с YAML frontmatter, оглавлением, метаданными
- **Главный Pipeline:**
  - `PDFToContextPipeline` - оркестратор всех компонентов с поддержкой статистики
- **DeepSeek-OCR микросервис:**
  - FastAPI приложение с vLLM для inference
  - HTTP API: `/ocr/page`, `/ocr/figure`, `/health`
  - Поддержка режимов: Tiny, Small, Base, Large, Gundam
  - Stub-режим для тестирования без vLLM
- **Модели данных:**
  - `BBox`, `TextBlock`, `ImageBlock`, `DrawingBlock`, `TableBlock`
  - `OCRBlock`, `OCRResponse`, `OCRMode`
  - `ContentType`, `LayoutType`, `RouteDecision`, `PageMetadata`
- **Документация:**
  - `pdf_to_context/README.md` - полная документация модуля
  - `pdf_to_context/ocr_service/README.md` - документация микросервиса
  - `requirements.txt` - зависимости основного модуля
  - `pdf_to_context/ocr_service/requirements.txt` - зависимости микросервиса
- **Эвристики маршрутизации:**
  - Native: текстовый слой + простой layout + низкая графика
  - OCR: нет текстового слоя / сложный layout / высокая графика
  - Hybrid: текстовый слой + embedded изображения/формулы

### Технические детали
- **Принципы проектирования:** SOLID, KISS, DRY
- **Приоритет точности:** режим `prioritize_accuracy=True` использует Base/Large OCR режимы
- **Интеллектуальный анализ:**
  - Определение layout (single/multi-column/complex/newspaper)
  - Оценка плотности текста (для выбора OCR режима)
  - Расчет покрытия графикой
  - Кластеризация векторной графики
- **Связи в IR:** reading_order между блоками по позициям (page, Y, X)
- **Структурный анализ:**
  - Автоопределение заголовков H1-H3 по font size/bold/паттернам
  - Идентификация списков (маркированные/нумерованные)
  - Построение иерархии разделов
  - Генерация оглавления (TOC)
- **Markdown вывод:**
  - YAML frontmatter с метаданными документа и IR статистикой
  - Оглавление с anchors и номерами страниц
  - Маркеры страниц в комментариях
  - Поддержка таблиц, изображений (base64), списков

### Зависимости
- PyMuPDF (fitz) >= 1.23.0
- pdfplumber >= 0.10.0
- Pillow >= 10.0.0
- requests >= 2.31.0
- PyYAML >= 6.0.1
- **OCR сервис:** vllm >= 0.3.0, fastapi >= 0.104.0, uvicorn

### Использование
```python
from pdf_to_context import PDFToContextPipeline

pipeline = PDFToContextPipeline(
    ocr_base_url="http://localhost:8000",
    prioritize_accuracy=True
)

markdown = pipeline.process("document.pdf", output_path="output.md")
```
