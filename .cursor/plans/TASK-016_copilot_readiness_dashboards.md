# TASK-016: Copilot Readiness — дашборды для оперативной смены ЦУП

## Контекст и цель

В чате 2026-05-18 выявлено, что вкладка «AI Readiness & Roadmap» в `docs/dashboards/tsup_as_is_dashboard.html` оперирует неточным счётом источников B-петли и KPI «60% green» агрегированно маскирует разрыв (нарушает Rule 0). Два независимых кросс-чека (Opus 4.7 / GPT-5.5) подтвердили:

- строгий счёт §6 каталога даёт **19 ID + 3 организационных входа** (не 27);
- расширительный счёт по §1–§4 — **27 источников, 18 green / 8 yellow / 1 red**;
- ошибочно отнесены к B-петле: `SYS-LOTUS`, `VOICE-RADIO`, `MAN-LOG-SHIFT`, `DOC-ACT-DELAY`, `DOC-ERP-CARDS` (это A-петля и B4);
- пропущены в green: `FEED-SITA`, `DOC-KYFO-LOG`;
- критпуть нужно расширить с GAP-03 + GAP-10 до **GAP-03 + GAP-10 + GAP-08**;
- AMOS-слой (TASK-014/015) и `matching.json` (TASK-012/013) упущены — их надо использовать как provenance, не плодить дубли.

**Цель TASK-016:** привести оба существующих дашборда ЦУП и один новый мокап к честной картине Rule 0: «видно, где данные есть, видно, где нет, видно, как они связаны». Три последовательных шага, каждый — отдельный файловый дифф.

## Не входит в scope

- Не переписывать `data_sources_catalog_TsUP.md` и `knowledge_gaps_TsUP.md` — они уже источник истины, только сверка.
- Не подключать live-источники к карточке рейса B2 — это mockup статикой.
- Не менять схему `cup.flights` (изменение `decision_traceability` идёт на UI-уровне, не SQL).
- Не трогать `matching.json`, `cup_overlay.json` — используем как есть.
- Не запускать batch / Claude API / OCR.

## Источники истины

- `docs/data_sources_catalog_TsUP.md` §1–§7 — каталог 30+ источников.
- `docs/knowledge_gaps_TsUP.md` GAP-01…GAP-10 — реестр пробелов.
- `docs/dashboards/tsup_as_is_dashboard.html` — методологический дашборд, вкладки 0–5.

## Шаг 3 — новый `b2_shift_board_mockup.html`

**Файл:** `docs/dashboards/b2_shift_board_mockup.html` (новый, статический HTML, ~500–700 строк).

**Что в нём:**

3.1. **Главный экран — Shift Board (очередь смены).**
- Список 5–7 фиктивных активных отклонений с полями: рейс, маршрут, ВС, текущий статус, SLA-таймер ближайший (T-6/T-3/T-2/T+1ч), severity, GAP-флаги.
- Сортировка по «времени до ближайшего SLA-дедлайна».
- Цветовая индикация freshness (зелёный/жёлтый/красный — по фиктивным timestamp'ам последних обновлений).
- На каждой строке кнопка «открыть карточку B2».

3.2. **Freshness-панель сбоку.**
- Список систем (Leonardo, DCS Astra, Meridian.OPS, KYFO, AFTN, METEO) с фиктивным «last sync timestamp».
- Если timestamp'ы расходятся между Leonardo / DCS / OPS — плашка `⚠ DESYNC (GAP-10 материализован)`. Иначе — `OK`.

3.3. **Drill-down — карточка рейса B2** (отдельная секция на странице, изначально скрыта).
- 5 панелей: Состояние ВС, Экипаж, Пасс./коммерция, Внешний контур (METEO/CBRS/NOTAM), **Журнал решений (пустой плэйсхолдер с пометкой GAP-03)**.
- Поля заполнены фиктивными данными из одного из рейсов очереди.
- Журнал решений: пустая форма с явной подписью **«⚠ GAP-03 — поле существует в дизайне, но в Meridian.OPS пока не пишется. Когда появится — здесь будут варианты/критерии/выбор/обоснование.»**

3.4. **Подвал страницы — Rule 0 disclaimer.**
- «Этот макет — переговорная демка для НС ЦУП. Все данные фиктивные. Зелёные источники — могут быть подключены сегодня (см. data_sources_catalog §1–§4). Красные пробелы (GAP-01, 03, 05) — показаны как пустые поля с пометкой, а не достроены.»

**Acceptance:**
- Открывается standalone в браузере без сервера.
- На странице явно отмечено: «mockup, не live».
- Freshness-плашка DESYNC показывается, потому что timestamps в моке расходятся (демонстрация GAP-10).
- Журнал решений визуально пуст с явной GAP-03 подписью (не «заглушки на будущее», а демонстрация дыры).
- Стилистика консистентна с `tsup_as_is_dashboard.html` (тёмная тема, IBM Plex Sans).

**Owner:** coder.
**Effort:** M (новый файл, ~600 строк HTML/CSS/JS статикой).

## Riski

- **R1 — cross-repo (D-023).** Шаг 2 трогает `todo/webBI/cup-tsup/*`. Если human не одобрит cross-repo прямо сейчас — Шаг 2 либо откладывается, либо делается без cross-repo (только в `Obligations`, как описание планируемых правок).
- **R2 — Rule 0 риск в Шаге 3.** Если фиктивные данные в Shift Board сделать слишком правдоподобными — могут быть восприняты как реальные. Митигация: в шапке и подвале — явная плашка «MOCK / фиктивные данные».
- **R3 — `matching.json` доступ из cup-tsup.** Файл лежит в `Obligations/output/cup_codifier/`. В cross-repo стандарт — копия в `todo/webBI/.../static/`. Дублирование данных — митигируется единым build-скриптом (вне scope этого TASK, см. TASK-013).
- **R4 — GAP-карта Severity×Effort×Phase в static HTML.** Без JS-фреймворка может быть громоздкой. Митигация: использовать SVG или CSS grid, не canvas/d3.
- **R5 — `decision_traceability = 0%` всегда.** Пока GAP-03 не закрыт. Это **не баг**, это и есть смысл — показать дыру.
