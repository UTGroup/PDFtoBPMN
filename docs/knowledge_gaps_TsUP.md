# Реестр knowledge gaps ЦУП (AS-IS)

> **Версия 2.1** — синхронизирована с §6 файла `input2/ЦУП_md/ANALYSIS_AS-IS_RCA_и_Сбойные.md`.
> Артефакт §7.1 шага 3 из аналитики AS-IS.
> Цель: каталог мест, где НС ЦУП / диспетчер / начальник ЦУП принимают решения **на основании данных, которых нет в системах**, либо данных, которые **не сохраняются** в машиночитаемом виде.

> **Cross-reference нумерации.** В этом файле сквозная нумерация GAP-01…GAP-10. В анализе (`ANALYSIS_AS-IS_RCA_и_Сбойные.md` §6) и в презентации используется собственная нумерация gap-01…gap-06 — это укрупнённая выборка пяти + одного нового. Соответствие см. в сводной карте в конце файла.

## Шкала влияния

- **Severity (S)**: `1` — блокирует ИИ-ассистент в данной точке, `2` — деградирует качество, `3` — некритично.
- **Effort (E)**: `S` (≤2 нед.), `M` (1–2 мес.), `L` (>3 мес., требует регуляторного/политического согласования).
- **Owner**: предполагаемый владелец закрытия пробела.

## GAP-10 — Несинхронность данных АСБ Leonardo ↔ DCS Astra ↔ Meridian.OPS *(новый в v2.1)*

| Поле | Значение |
|---|---|
| **DP** | B2 (выбор «перенести / отменить / совместить») |
| **Что теряется** | При изменении времени рейса в B2 решение распространяется по трём системам **асинхронно**: расписание — в Meridian.OPS, продажи и ремарки приоритетов — в АСБ Leonardo, регистрация — в DCS Astra. До формального согласования у НС ЦУП нет единой картины «текущее состояние пакса × текущее состояние рейса × текущее состояние ВС» |
| **Якорь** | `КД-РД-Б1.041-04` §10–§14 (изм.32) — все три системы упомянуты как обязательные источники для решений по пассажирам |
| **Severity** | 2 (не блокирует MVP, но обязательно вылезет на пилоте) |
| **Effort** | M |
| **Owner** | ИТ ЮТэйр + ЦУП |
| **Митигация** | (a) Change Data Capture (CDC) из всех трёх систем; (b) общая событийная шина (event-bus) с публикацией изменений по рейсу; (c) сводная карточка рейса в Meridian.Web |
| **Соответствие** | gap-06 в `ANALYSIS_AS-IS_RCA_и_Сбойные.md` §6 и в слайде 12 презентации |
