Контекст: 3 уровня анализа задержек по КД-ДП-Б8.007-05 §11 табл.1: оперативный (диспетчер/смена), ежедневный (до 11:00 тюм. — нач. ЦУП), глубокий (нач. ЦУП → ген.директор, корректирующие действия по ДП-М1.003).
Обзорная диаграмма снята с публикации. Эскиз заменён стабильными карточками DP ниже. Каноническая визуализация процесса доступна как BPMN: RCA_AS-IS.bpmn.

Decision points цикла A — детально

A1Диспетчер ЦУП — предв. формулировка причины задержки + IATA≤15 мин · РД-Б8.005-09 §14.2›
Входы: MVT/AFTN/SITA, сообщения Ю-Ти-Джи (Модуль OPS, тел.), КВС/экипаж по радио/телефону, контекст из Meridian.Ops.
Выход: запись в Meridian.Ops с предварительной формулировкой и кодом IATA.
Узкое место: голосовые уточнения не фиксируются (см. GAP-01).
Возможность ИИ: заполнение чек-листа источников опроса + предложение IATA-кода по тексту входящих сообщений.
A2НС ЦУП — окончательная формулировка + AHM 730по смене · §14.2 ш.3,6›
Входы: результат A1, уточнения от ОПДО / ДОНО / СПиОУ / ЦУТО ВС, e-mail в Lotus Notes, журнал смены.
Выход: согласованная запись в Meridian.Alliance, попадает в отчёт UT-DSP.1-01.1.
Узкое место: агрегация в голове НС ЦУП (см. GAP-05 — бумажный журнал смены).
Возможность ИИ: сводка всех источников за смену по конкретному рейсу/задержке.
A3Начальник ЦУП — анализ материалов и решение об эскалациидо 11:00 тюм. ежедневно · КД-ДП-Б8.007 §11›
Входы: отчёт UT-DSP.1-01.1, акт на задержку (ПДС а/п), отчёт представителя.
Выход: Lotus Notes — уведомления руководителям подразделений-виновников; накопление в ИС «Производственная отчётность».
Узкое место: акты разнородны по формату (см. GAP-02).
Возможность ИИ: авто-классификация актов + предложенный список адресатов уведомления.
A4Начальник ЦУП → ген.директор — корректирующие действиянеделя/месяц/год · РИ-М1.016 §9; ДП-М1.003›
Входы: отчёт UT-DSP.1-06 (регулярность, 21 категория задержек).
Выход: запуск корректирующих/предупреждающих действий (по ДП-М1.003), спец.аудиты подрядчика (РД-М1.014).
Готовность: высокая — данные структурированы.
Возможность ИИ: детектор повторяющихся коренных причин, ранжирование по эффекту на регулярность.

AS-IS поток данных: оперативное управление регулярностью v2.1 · 12 многофакторных входов (8+4)

Триггер B-петли: каждое прогнозируемое или фактическое отклонение в плане полётов (без порога). На уровне B2 регламент требует рассмотреть не менее двух вариантов разрешения и зафиксировать обоснование. SLA-таймеры из КД-РД-Б1.041-04 (изм.32): −6ч DEGR/CVIP/PDTS · −3ч/−2ч трансферный лист · +1ч контроль ФАП-82 (KYFO) · флаг t/t* в фильтре подмены ВС.
Обзорная диаграмма снята с публикации. Поток B1–B4 описан карточками ниже и каноническим BPMN: Operational_Regularity_AS-IS.bpmn. Входы M1–M12 и GAP-03/GAP-10 сохранены в таблицах и карточках этой вкладки.

Decision points цикла B — детально

B1Диспетчер ЦУП + смежные дежурные — сбор оперативной картины≤30 мин · триггер: каждое отклонение · КД-ДП-Б8.007 §11; РД-Б8.005-09 §14.2 ш.1›
Входы: поток MVT/AFTN/SITA + IATA-коды из Meridian.Ops + метео + сообщения от ОПДО/ДОНО/СПиОУ/ЦУТО ВС.
Выход: сводная картина по конкретному отклонению (передаётся в B2).
Готовность: высокая — большинство данных машиночитаемо.
Возможность ИИ: Co-pilot диспетчера — авто-сборка картины по конкретному рейсу.
B2НС ЦУП — окончательное решение по отклонениюминуты–часы (на рейс) · РД-Б8.005-09 §14.1.3 + КД-РД-Б1.041-04 §6, §10–§17 (изм.32)›
Входы базовые (8): метео/НОТАМ; парк ВС (AOG, MEL, винглеты, темп.ограничения); экипажи (резерв, раб.время); маршруты/топливо/запасные а/д; наземное обслуживание; коммерц. загрузка/приоритеты; слоты ЦБРС; внешние заявки.
Входы v2.1 (4, КД-РД-Б1.041-04 изм.32): DEGR/CVIP/PDTS из АСБ Leonardo (T-6ч); t/t* в Meridian.OPS (фильтр подмены ВС); KYFO (контроль ФАП-82, T+1ч); DCS Astra (трансферный лист T-3ч/-2ч).
Выход: решение + команды исполнителям + СМС-рассылки + РД в МТУ Росавиации (>2 ч / >6 ч).
Узкие места: обоснование не сохраняется (GAP-03, КРИТИЧНО — главный блокер MVP); рассинхрон АСБ↔DCS↔OPS (GAP-10/gap-06, новый в v2.1).
Возможность ИИ: Co-pilot НС ЦУП по B2 — генератор альтернатив с карточкой обоснования (учтённые ограничения, SLA, ожидаемый эффект, риски).
B3Исполнители — команды по регламентированным каналамминуты · РД-Б8.005-09 §15.1.3.2.2.1–8; КД-РГ-147(148)-08 табл.1–5›
Входы: команды НС ЦУП через Meridian.Ops, 148-08, Lotus, ГГС/тел., СМС.
Исполнители: ДЦ Ю-Ти-Джи, ЦУТО ВС, СПиОУ, ДОНО, ДУТиЗ, КЦ, ОКР, ДО ЦУП, менеджер расписания.
Выход: подтверждение исполнения, факт-вылет, обновление ПП.
Готовность: высокая (каналы регламентированы).
B4Иерархическая эскалация — нач. ЦУП / нач. ЛДпо факту · РД-Б8.005-09 §14.1.4›
Триггер: отклонение выходит за рамки компетенции НС ЦУП (не ERP).
Входы: сводка по B1+B2, телефонная связь.
Выход: согласование решения вышестоящим руководителем → возврат в B3.
Out of scope основной B-петли: ERP/РГ-128 (АНВ/АП) — отдельный проект, см. GAP-06; «Сбойная ситуация» по §15.1.3.3 — фаза 2 (плейбуки КК62-26), GAP-09.

Риски и ограничения

⚖Регуляторика — ИИ только рекомендуетРД-Б8.005-09 §14.1.3, §15.1.3.3.6›
Окончательная ответственность за управление ПП — на НС ЦУП и начальнике ЦУП. ИИ-ассистент не может заменить решение, только подготовить варианты и обоснование. Якорь — ВК РФ, ФАП-128, ФАП-82, РПП-2017.
📋Сертификация СМКДП-М1.003 / РД-М1.014›
Изменения процедур ЦУП проходят через управление корректирующими действиями (ДП-М1.003) и аудит качества (РД-М1.014). Выкатка ИИ в продуктив требует записи в СМК.
🚨ERP / RG-128 — вне scope MVPкритичность ошибки›
Кризисный контур (АНВ/АП) не входит в MVP — критичность ошибки несопоставима с RCA по задержкам. Отдельный проект.
🔒Vendor lock — Meridian.AllianceКД-ДП-Б8.007 §12.1.5›
Meridian.Alliance — внешний вендор. Доступ к данным согласовывать (cloud.utair.ru). Возможны ограничения на запись и интеграции.
