Что мог бы добавить co-pilot

Phase 0 (read-only): Собирать карточку B2 автоматически из 18 зелёных источников, считать SLA-таймеры, сигнализировать о DESYNC между системами.
Phase 1 (журнал решений + ДУТиЗ feed): Предлагать варианты по аналогии с прошлыми решениями смены, подсказывать критерии, проверять регламент.
Phase 2 (голос + OCR): Транскрибировать переговоры по ГГС, OCR актов от ПДС а/п, классификация по 21 категории.
Rule 0 disclaimer. Этот макет — переговорная демка для НС ЦУП. Все рейсы, времена, бортовые номера и статусы сгенерированы. Цель — обсудить, нужен ли такой формат и какие поля в реальности важны.
  • Зелёные значения (например, METAR, слоты, KYFO timestamps) — соответствуют источникам, которые сегодня доступны read-only (см. data_sources_catalog_TsUP.md §1–§4, готовность=green). Эти 18 источников могут подключаться без переделки источника.
  • Жёлтые значения с пометкой ⚠ — соответствуют GAP-08 (устные приоритеты ДУТиЗ) и GAP-10 (DESYNC между 3 системами). Они показаны явно, а не «достраиваются» дизайнером.
  • Пустые поля журнала решений (панель «Журнал решений B2») — это и есть GAP-03 в живом виде. Эти поля сегодня не пишутся ни в Meridian.OPS, ни где-либо ещё. Когда пишутся — поля начнут заполняться.
  • Goalpost для разговора: «такая раскладка вам подходит? Что важно добавить? Что убрать?»
